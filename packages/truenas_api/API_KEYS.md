# Native API-key lifecycle: bounded TrueNAS 25.10 contract

This workspace manages API keys for the **current local, non-builtin account**: safe inventory, creation, name/expiry edits, rotation and deletion. It is not full WebUI credential parity. Other accounts, directory-service identities, legacy/system keys, token-derived credentials, sessions without provable identity and STIG-prohibited changes remain blocked. Creation and rotation include one-time delivery of the newly returned credential; existing key values and hashes are never requested for display.

Contracts are pinned to the official `TS-25.10.1` middleware source. Development and verification used public source, synthetic transports, synthetic Flutter repositories and connector-free fixtures only. No appliance contact, authentication or real write was performed.

## Public contract and effects

| Operation | Exact public RPC shape | Native behavior |
| --- | --- | --- |
| Current identity | `auth.me []` | Uses only bounded `pw_name`, matched to the connected session summary. No returned attributes, password or two-factor configuration are retained. |
| Current credential | `auth.sessions [[["current","=",true]], {"limit":2,"select":["id","current","internal","secure_transport","credentials","credentials_data"]}]` | Requires exactly one current external secure session; stores only its ID, credential type and API-key ID. Password/two-factor sessions have no protected key; API-key sessions protect their matching key. Token parent chains are not followed. |
| Local account | `user.query [[["username","=",username],["local","=",true]], {"limit":2,"select":["id","username","local","builtin","locked","roles"]}]` | Requires one matching local account. Builtin, locked and role-less accounts are not eligible. The complete sorted role list participates in drift checks. |
| Security policy | `system.security.config []` | Reads only the boolean STIG flag into inventory. STIG blocks all key writes. |
| Key inventory | `api_key.query [[["username","=",username]], {"limit":129,"select":["id","name","username","user_identifier","created_at","expires_at","local","revoked"]}]` | At most 128 unique key IDs, own-account filter and allowlisted parser. The select projection specifically excludes `keyhash`, `key` and remote revocation messages. |
| Create | `api_key.create [{"name":name,"username":username,"expires_at":utcOrNull}]` | Inserts a new key record, generates its hash and regenerates authentication configuration. Returns a new value once. |
| Name/expiry | `api_key.update [id,{"name":name,"expires_at":utcOrNull,"reset":false}]` | Changes the database record. This server path does **not** immediately regenerate PAM configuration; no instant login invalidation is promised. |
| Rotate | `api_key.update [id,{"name":name,"expires_at":utcOrNull,"reset":true}]` | Replaces the value and hash, clears revoked state and regenerates authentication configuration. Existing clients must adopt the replacement value. |
| Delete | `api_key.delete [id]` | Permanently removes the key and regenerates authentication configuration. Successful result must be literal `true`. |

The public API has no direct `api_key.revoke` method: it is private and is never invoked. Native deletion removes future use of the key but **does not terminate already-authenticated sessions**. Rotation also does not promise session termination. Server privilege checks remain authoritative; method availability is never interpreted as authority to modify another user's credentials. [Public key models](https://github.com/truenas/middleware/blob/TS-25.10.1/src/middlewared/middlewared/api/v25_10_0/api_key.py), [key lifecycle and privilege checks](https://github.com/truenas/middleware/blob/TS-25.10.1/src/middlewared/middlewared/plugins/api_key.py), [session models](https://github.com/truenas/middleware/blob/TS-25.10.1/src/middlewared/middlewared/api/v25_10_0/auth.py), [session identity implementation](https://github.com/truenas/middleware/blob/TS-25.10.1/src/middlewared/middlewared/plugins/auth.py).

## Review, protection and result validation

Every request uses an inventory object issued by the exact current SDK session. Reviews are one-use, last five minutes and require an exact action/ID/name confirmation. Forged, reused or refreshed reviews are invalid. Load, review and execution all use bounded safe reads. Immediately before dispatch the SDK checks endpoint, username, user ID, role membership, session ID/type/current-key reference, eligibility, STIG state and complete sorted public key identity again. This includes name, owner, creation time, expiry, local flag and revocation state. A concurrent secret-only rotation can preserve all those fields, so this projection cannot prove an unchanged credential value or version; no hash is fetched to make that comparison. Current authentication keys cannot be renamed, rotated, expired or deleted in this session; use a separate supported password/OTP session.

Names must contain 1–200 non-control characters with no surrounding whitespace. Duplicate names visible in this account are rejected; global uniqueness is ultimately checked by TrueNAS. New expiry must be between one minute and one year ahead, or explicitly absent. Payloads normalize expiry to UTC integer-second precision because the server stores integer Unix seconds. The editor requires a complete real calendar date ending in `Z`, rejecting date overflow rather than accepting Dart's normalization. Server creation timestamps may be explicitly UTC ISO, protocol `$date`, or naive ISO known from the source's UTC clock; naive expiry is rejected. Source: [UTC helper](https://github.com/truenas/middleware/blob/TS-25.10.1/src/middlewared/middlewared/utils/time_utils.py).

Create/update receipts are validated against requested account, numeric local owner, ID, name and expiry. Creation returns its local owner as a canonical numeric string while query/update extend that value to an integer; only canonical positive numeric owners are normalized, never legacy markers, directory SIDs or arbitrary strings. Existing-key responses must preserve creation identity; ordinary edits must preserve revoked state. Create/rotate secrets must be the exact returned positive key ID, a hyphen, then 64 ASCII letters/digits. An ordinary update containing any unexpected key value is uncertain, not displayed. Source: [key string generation](https://github.com/truenas/middleware/blob/TS-25.10.1/src/middlewared/middlewared/utils/crypto.py).

Preflight failure dispatches no mutation and reports a fixed redacted message. Once a write is sent, **every** exception, timeout, disconnect, malformed receipt or mismatched result is unknown, including permission-shaped errors: the database change can precede later authentication-file failures. Unknown state retains the shared SDK mutation fence and Flutter operation lock. Refresh never clears it, no write is retried, and same-server fresh reconnection plus explicit acknowledgment does not claim rollback or success. Cross-family tests cover API-key pending/unknown blocking cloud credentials, system updates, replication and cloud sync; cloud-credential pending/unknown also blocks API keys. No transactional compare-and-swap exists, so a concurrent administrator can still race after the last read.

## One-time secret boundary

`ApiKeyOneTimeSecret` is a consumable transient wrapper with a redacted string representation. `take()` succeeds at most once; `discard()` drops its retained reference. `ApiKeyResult.withoutSecret` is the only form stored in the Flutter controller. The live secret is returned directly to the short-lived delivery dialog, never placed in a provider, session profile, credential vault, cache, navigation argument persistence or diagnostics.

After an explicit privacy acknowledgment the dialog reveals the new value. Copying is a separate user action and warns about system clipboard history; there is no automatic copy or clipboard deletion. The delivery observer is registered **before** awaiting the mutation so backgrounding cannot be missed while Flutter suppresses dialog frames. Any backgrounding, close, disposal or connection change discards held material. A secret arriving after session replacement or while delivery has expired is discarded without display. The API key cannot be recovered by rereading inventory or replaying creation.

This is reference-lifetime control, not guaranteed memory erasure: Dart strings, OS clipboard history, screenshots and external password managers can retain values. The UI states those limitations. There is no OS screenshot-blocking claim. The health donut shows active/expired/revoked counts from current inventory; expiry status uses the device clock and is not a test of authentication viability.

## Verification and open scope

The SDK suite covers exact payloads, projected reads, account/current-key protection, unsupported releases and metadata, expiry normalization, calendar validation, fresh identity and role drift, one-use reviews, receipt validation, unknown fences, cross-family locks and generic-admin bypass rejection. Flutter tests cover no-secret controller state, late-result disposal, explicit reveal/copy, lifecycle/session invalidation, exact review and compact/large-text layouts. The preview rejects every write and returns no generated credential.

Remaining work includes other-account administration, directory-service and legacy keys, protected-session rotation with coordinated migration, session termination, server-clock expiry evidence, platform screenshot defenses and real-appliance acceptance testing. Nothing here claims full WebUI parity or official TrueNAS affiliation.
