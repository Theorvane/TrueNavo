# Audit storage, retention and export native contract (TD-079)

Source: TrueNAS middleware tag [TS-25.10.1 audit API](https://github.com/truenas/middleware/blob/TS-25.10.1/src/middlewared/middlewared/api/v25_10_1/audit.py), [audit service](https://github.com/truenas/middleware/blob/TS-25.10.1/src/middlewared/middlewared/plugins/audit/audit.py) and [audit backend](https://github.com/truenas/middleware/blob/TS-25.10.1/src/middlewared/middlewared/plugins/audit/backend.py).

The native workspace reads `audit.config` only on an authenticated stable 25.10 session. It projects bounded scalar retention, quota/reservation thresholds, remote-logging flag and used/available audit dataset bytes. Complete configuration, including enabled-service lists, is held only as a private keyed digest for drift checks. The usage ring is a snapshot of dataset space, not evidence of event coverage, remote delivery or remaining retention capacity.

The native editor exposes only changed retention, reservation, quota, quota-fill warning and quota-fill critical fields through `audit.update`. Retention is 1–30 days, reservation and quota are 0–100 GiB, warning is 5–80%, and critical is 50–95%. Quota must be at least reservation; zero disables quota only when reservation is also zero. A changed quota is rejected locally when current dataset-plus-snapshot usage would already exceed the proposed warning threshold. A changed value requires a fresh standalone READY/FULL_ADMIN/healthy-boot/no-job review, stable host and boot, a five-minute one-use lease, exact full-host confirmation, explicit dataset-impact acknowledgement, and separate evidence-loss acknowledgement for a shorter period. Review and execute independently re-read protected configuration; only changed fields are submitted. The response and a separate readback must match the saved configuration without the continuously changing `space` observation. After-dispatch errors or ambiguous receipts are `unknown`, never retry or rollback claims. The unknown state fences other native maintenance writes for the session.

TrueNAS may compare and adjust audit ZFS quota, reservation and alert properties inside `audit.update` even when the payload contains only retention, before its datastore update. Lower retention can accelerate eventual cleanup of local records and reports; the RPC itself is not proof cleanup happened. The workspace does not expose HA changes, remote-controller queries or raw event payloads. Generic `audit.config`, `audit.update` and `audit.export` schema forms are blocked in favor of protected native routes.

The export route accepts one service, an exact UTC interval of at most 31 days, optional exact username/result filters, CSV/JSON/YAML format and an explicit 10,000-row limit. It requires separate acknowledgement of full sensitive payloads, the temporary server-side artifact and the row cap. A five-minute review is bound to the full host and healthy standalone boot state. Exact confirmation dispatches `audit.export` once. Manual checking verifies the same job ID, method, HMAC-bound arguments and terminal result before invoking `core.download` for `audit.download_report`. Only a same-job relative `/_download` URL is accepted. The certificate-pinned session transport caps the gzip response at 16 MiB, then verifies the download job and host again before releasing one-use bytes. Before Android document handoff, the app bounds decoded data to 64 MiB; verifies the gzip CRC32 and ISIZE; admits only a checksum-valid USTAR directory named for the canonical report UUID plus zero or one expected `part_00000` regular member; rejects unsafe paths, links, extra members, non-zero padding and malformed terminators; and validates the selected JSON-list, CSV-record or parsed YAML-list-of-maps shape at no more than 10,000 rows. Bytes are wiped after every save outcome. Neither job is automatically retried. Any ambiguous post-dispatch state releases no file and fences maintenance writes until independent original-server inspection and reconnection acknowledgement. This structural semantic check does not prove audit-event field-schema conformance, record completeness, report authenticity, extraction by another tool or destination durability.

Verification uses synthetic in-memory JSON-RPC only. No supplied NAS credential, live write, live audit query, report job, download job or command execution is used in this increment. Independent live acceptance and data-loss recovery policy remain outstanding.
